# 局域网屏幕共享系统 —— 需求分析与技术方案

> 项目：`screen_cast_cpp`（Windows C++17）
> 版本：v3.6（阶段一 单播 1:1 + 阶段三 组播 40 客户端 + 自适应码率 + 自动重连 全部完成）
> 代码量：约 3000 行（不含 FFmpeg 第三方库）
> 配套文档：`../README.md`（运行手册）、`../交付报告.md`（交付与压测数据）

---

## 1. 项目概述

开发一套**局域网屏幕共享软件**，教师端将屏幕画面实时共享给 30~40 个客户端观看，
要求**高清原画、高 FPS、低延时**，用于课堂教学/会议投屏场景。

| 维度 | 目标值 |
|---|---|
| 并发客户端 | 40 个（组播模式，一份带宽服务所有客户端） |
| 分辨率 | 1080p（源 2560x1600 实测） |
| 帧率 | 30–60 FPS（受屏幕内容与编码器影响） |
| 端到端延迟 | < 100ms（实测 16–63ms） |
| 协议 | UDP（单播 1:1 联调 / 组播 40 并发） |
| 丢包容忍 | FEC 前向纠错 + 智能关键帧请求（实测 1% 丢包下 80% 受损帧被救回） |

## 2. 需求分析

### 2.1 功能需求
1. **教师端**：采集本机屏幕 → 编码 → 发送；带 GUI（画面预览、清晰度切换、差分开关、组播模式）
2. **客户端**：接收 → 重组 → 解码 → 窗口渲染；带 GUI（中文标题栏实时显示 教师端IP/帧率/丢包率/延迟/队列）
3. **实时性**：低延迟优先，客户端丢弃积压帧保实时
4. **带宽优化**：差分投屏（静态画面跳过编码）、组播（一份流量服务 N 个客户端）
5. **健壮性**：丢包自愈（FEC + 关键帧重建）、编码器驱动降级（NVENC → libx264）、窗口可缩放

### 2.2 非功能需求
- **低延迟架构**：无 B 帧、零延迟编码、`LOW_DELAY` 解码、单线程解码、网络线程直接解码入队
- **安全边界**：收包重组层全量边界校验（防恶意/损坏包头越界写）
- **跨线程安全**：原子统计、锁保护共享状态、停止路径幂等
- **中文界面**：全宽字符 API（`W` 系）+ UTF-8 源码，控制台 `SetConsoleOutputCP(CP_UTF8)`

## 3. 技术选型

### 3.1 屏幕捕获方案对比（GDI / DXGI / D3D11）

| 方案 | 原理 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **GDI** (`BitBlt`) | 从屏幕 DC 逐像素拷贝 | 实现简单、兼容性最好 | 只能拿**合成后的位图**，无脏区信息；CPU 拷贝 1080p 全屏开销大；被遮挡窗口内容错误 | 不选 |
| **DXGI Desktop Duplication** | `IDXGIOutputDuplication::AcquireNextFrame` | **硬件加速**、自带 **脏区矩形 (DirtyRects)**、双缓冲；Win8+ 官方推荐 | 需要 COM/线程模型；`DXGI_ERROR_ACCESS_LOST` 需重建 | ✅ **选用** |
| **D3D11 直接渲染** | 直接操作交换链 | 延迟最低 | 屏幕捕获本身仍需 Desktop Duplication；复杂度高 | 仅用于**客户端显示** |

**结论**：捕获用 **DXGI Desktop Duplication**（脏区驱动差分投屏），客户端显示用 **D3D11**。

### 3.2 编码方案（FFmpeg）

| 编码器 | 适用 | 配置要点 |
|---|---|---|
| **h264_nvenc**（首选） | NVIDIA 显卡硬件编码，CPU 占用极低 | `preset=p1`（最快）、`tune=ull`（超低延迟）、`rc=cbr`、`zerolatency=1` |
| **libx264**（自动回退） | 无 NVIDIA / 驱动过旧 | `preset=ultrafast`、`tune=zerolatency`、`keyint=60:min-keyint=60:scenecut=0` |

通用低延迟配置：**无 B 帧**（`max_b_frames=0`，消除最大延迟源）、`gop_size=fps*2`、`AV_CODEC_FLAG_LOW_DELAY`、单线程。
不设 `GLOBAL_HEADER`：关键帧自带 SPS/PPS，客户端拿到关键帧即可自同步，无需带外配置。

### 3.3 网络方案（UDP）

- **传输**：UDP（实时性优先，容忍少量丢包，靠 FEC/关键帧重建兜底）
- **单播模式**（阶段一）：教师端 `sendto(客户端IP)`，1:1 联调
- **组播模式**（阶段三）：视频流发往组播组 `239.255.1.1:5004`，所有客户端 `IP_ADD_MEMBERSHIP` 加入同一组 → **一份带宽服务 40 客户端**
- **控制通道**（KEYFRAME 请求）：始终**单播直达教师端**（`5005` 端口），组播下也复用单播
- **组播细节**：`IP_MULTICAST_TTL=1`（限本网段）、`IP_MULTICAST_LOOP=1`（本机回环联调）、`SO_REUSEADDR`（多进程绑同端口收组播）；交换机需开启 **IGMP Snooping**
- **MTU**：整包 < 1472 字节（1500 - IP20 - UDP8），避免 IP 分片

### 3.4 解码与渲染方案
- **解码**：FFmpeg `avcodec`（H.264），`thread_count=1` + `LOW_DELAY`，NV12 → BGRA（swscale）
- **渲染**：D3D11 交换链 + 全屏四边形采样纹理，保持宽高比黑边填充，窗口缩放自动重建交换链

## 4. 系统架构

### 4.1 模块划分

```
screen_cast_cpp/
├── capture/    DXGI 桌面捕获（脏区）
├── encode/     FFmpeg H.264 编码（NVENC/libx264 自动降级 + 缩放）
├── decode/     FFmpeg H.264 解码（NV12→BGRA，SPS 自同步）
├── render/     D3D11 窗口渲染
├── net/        UDP 封装（单播/组播）+ 客户端收包线程
├── core/       Streamer 推流引擎（采集/编码/差分/发送/统计）
├── ui/         教师端预览缓冲与绘制
├── packet/     分包协议（20B 头）+ 收包重组（FEC 恢复）
├── teacher_gui.cpp    教师端 GUI（预览 + 清晰度 + 差分 + 组播）
├── teacher_cli.cpp    教师端控制台
├── client_gui.cpp     客户端（解码渲染 + 中文状态标题栏）
├── client_console.cpp 客户端（解码统计）
├── diag_dirty.cpp / diag_decode.cpp / diag_fec.cpp  诊断工具
└── stress_test.sh     组播压力测试脚本
```

### 4.2 线程模型

**教师端（Streamer）**
```
主线程(GUI) ──▶ setQuality / setDifferential / setAdaptive / start / stop（原子标志 + 锁）
采集线程 ──▶ DXGI 捕获 → 预览回调 → 差分判定 → 编码 → 分包 → sendto
控制线程 ──▶ recvfrom(5005) → "KEYFRAME" 置位 keyframeReq_ / "REPORT:千分比" 更新丢包表 → AIMD 自适应调码率
```

**客户端（ClientReceiver）**
```
网络线程 ──▶ recvfrom(5004) → 丢帧检测 → 重组(FEC 恢复) → 解码 → 入队
主线程(GUI) ──▶ 弹队列 → D3D11 present → 每秒刷新标题栏统计
```

### 4.3 数据流

```
教师端: 屏幕 → DXGI 捕获(BGRA+脏区) → 差分判定 → swscale→NV12 → H.264 编码
      → 分包(20B头+可选FEC奇偶) → UDP(单播/组播)
客户端: UDP → 重组(校验/去重/FEC恢复) → H.264 解码 → NV12→BGRA → 队列
      → D3D11 渲染 → 窗口显示
```

## 5. 详细设计

### 5.1 捕获模块（DXGI Desktop Duplication）
- `AcquireNextFrame` 获取脏区矩形列表与桌面纹理，双缓冲拷贝到 CPU BGRA
- 首帧 / 分辨率变化 / `DXGI_ERROR_ACCESS_LOST` 自动重建
- **脏区坐标校验**：裁剪到源分辨率范围内，防驱动异常
- 统计脏区面积占比 → 差分投屏判定依据

### 5.2 差分投屏（核心带宽优化）
```
变化面积占比 dirtyRatio = 脏区面积 / 全屏面积
if (dirtyRatio < 2% && 距上次发送 < 2s) → 跳过本帧编码（客户端沿用上一帧）
else → 编码发送
```
- **2 秒保活**：静态画面也至少每 2 秒发一帧（关键帧），保证新客户端可入画
- 实测：静态屏发送 345 帧 vs 跳过 267 帧，省带宽约 44%

### 5.3 分包协议（20 字节头，类 RTP）

```
#pragma pack(1)
uint32 magic     // 0x534C4142 ('SLAB')
uint16 frameId   // 帧序号（递增）
uint16 fragCount // 数据分片总数
uint16 fragIndex // 分片序号（0..fragCount-1；奇偶片 fragCount..fragCount+K-1）
uint8  flags     // bit0=关键帧  bit1=FEC奇偶片
uint8  reserved
uint32 ptsMs     // 采集时刻（延迟统计）
uint32 payloadLen
#pragma pack(pop)   // 共 20 字节

kMaxFragPayload = 1452 - 20 = 1432 字节/片
```

### 5.4 FEC 前向纠错（丢包恢复）

**发送端**：帧数据分片数 ≥ 4 时，附加 2 个 XOR 奇偶分片：
- `parity0` = 偶索引数据分片异或（分片 0,2,4,...）
- `parity1` = 奇索引数据分片异或（分片 1,3,5,...）
- 分片零填充到整长参与异或；奇偶片长度 = `kMaxFragPayload`

**接收端（重组层）**：数据分片未收齐时尝试恢复
- 每组合计缺失 ≤ 2 片、且对应组奇偶片已收到 → 按 `缺失片 = 组奇偶 XOR 该组其余已收片` 重建
- 恢复能力：任意 1 片丢失 **100% 恢复**；不同组的 2 片丢失可恢复；同组 2 片/超过 2 片 → 放弃（客户端请求关键帧重建）
- 恢复的尾分片可能带尾部零填充 → 对 H.264 解码器无害（Annex-B 忽略尾随零字节）
- 小帧（<4 片）不加奇偶：丢片损失小，奇偶开销不划算

**实测**：1% 随机丢包下 **80% 的受损帧被救回**（44/55）；3% 时大关键帧（~140 片）丢失超 K=2 上限属设计极限（LAN 实际丢包 << 1%）

### 5.5 收包重组
- 按 `frameId` 归帧、按 `fragIndex` 归位；重复包忽略
- **全量边界校验**：magic、payloadLen、fragCount（≤256）、fragIndex、跨包一致性
- 超时清理（100ms 未收齐丢弃），防内存膨胀
- 丢帧统计：按 `frameId` 间隙累计（`gap ≤ 512` 防乱序/重置误报）

### 5.6 关键帧策略（三机制协同）

| 机制 | 位置 | 规则 | 目的 |
|---|---|---|---|
| **智能请求** | 客户端 | 入画前 / 丢帧增长 / 3 秒无帧 才请求（300ms 合流） | 稳态控制流量≈0 |
| **请求限流** | 教师端 | 1 秒最多强制 1 个 IDR | 防 40 客户端请求风暴（组播下 1 个 IDR 服务所有客户端） |
| **周期性自愈** | 教师端 | 距上次 IDR 超 2 秒强制 | 差分跳过会拖慢编码器 GOP 计数，保证关键帧 ≤2s 必达 |
| **断流重连(v3.6)** | 客户端 | 断流 >5s 触发：重置解码预热 + 序列追踪 + 300ms 关键帧请求 | 教师端恢复后 0.3~1s 自动入画 |

### 5.6.1 自适应码率协议（v3.6）

**上报（客户端 → 教师端）**：随 HELLO 心跳每 2s 发送 `REPORT:<丢包率千分比>`（如 `REPORT:35` 表示 0.35% 丢包）：
- 统计窗口内**帧数 ≥2 才计损**（防静态桌面单帧丢失误报 100%）
- 丢包率经 **EMA 平滑**（0.2 系数）抑制抖动
- 断流 >3s 上报 `1000`（100% 丢包），教师端立即降码率

**控制（教师端 AIMD，每 1s 聚合最差客户端丢包率）**：
```
丢包率 ≥ 3%   → 目标码率 × 0.8（-20%，1s 冷却，独立时间戳）
丢包率 ≤ 0.5% 且持续 5s → 目标码率 × 1.1（+10%，5s 冷却）
0.5% ~ 3%     → 保持（滞回带，防震荡）
夹持范围      → [400 kbps, 手动/预设上限]
```
- 多客户端取**最差者**（保证所有客户端可跟随）；丢包表 5s 过期清理
- 下降/上升冷却时间戳**独立**：拥塞时不被慢速探升冷却误延迟降速
- **编码器重建**：`onFrame` 检测目标码率与当前编码器初始化值不一致 → 重建编码器并强制 IDR，客户端无感切到新码率
- 入口：GUI「智能码率」开关（实时切换）/ `teacher_cli --adaptive`

### 5.6.2 自动重连（v3.6）
- 客户端断流 **>5s 无帧**判定断流，**上升沿单次触发**：
  1. `decodePrimed=false` → 接收线程恢复 300ms 间隔关键帧请求
  2. `requestReset()` → 清空帧序号追踪（防教师端重启后帧号回绕造成虚假丢包）
  3. `decoder.close()` → 强制重新同步（教师端重启后分辨率/SPS 变化也能干净恢复）
- 标题栏显示「连接中断 - 自动重连中...」；教师端恢复后 **0.3~1s 自动入画**，标题自动复位
- **线程安全**：`FFmpegDecoder` 内部互斥锁串行化 GUI 线程 `close()` 与解码线程 `decode()`（消除 `avcodec_free_context` 与 `send_packet` 并发崩溃）；解码线程入队前判空丢弃重连竞态中的过期帧

### 5.7 解码模块
- **懒初始化 + 仅用含 SPS 的同步帧建解码器**（防止用 P 帧初始化导致永久无法解码）
- `LOW_DELAY` + 单线程，NV12 → BGRA（swscale，分辨率变化自动重建）
- 少数 P 帧不产出画面（编码器码率控制偶发跳帧）属正常：客户端沿用上一帧，下个 IDR 自愈

### 5.8 渲染模块（D3D11）
- 交换链 + 全屏四边形采样，保持宽高比黑边填充
- 窗口缩放自动重建交换链；最小化时跳过渲染（防除零）
- `setTitle()` 动态更新标题栏（宽字符）

### 5.9 GUI 设计

**教师端**（全宽字符 API）
```
[IP/组播组输入框] [清晰度下拉] [差分投屏☑] [变化区域] [智能码率☑(v3.6)] [组播模式☑] [开始推流]
[状态栏: 采集/发送/差分跳过/码率/包数 + 目标 X kbps(自适应时)]
[桌面预览区: BGRA 缩略图 + 可选脏区高亮, 30fps 刷新]
```
- 组播模式下输入框变**组播组地址**（默认 239.255.1.1，可编辑，多教室并行改不同组）
- **智能码率开关**：推流中可实时切换；开启后按客户端上报丢包率自动调码率（见 §5.6.1）

**客户端**（全宽字符 API）
- 标题栏每秒刷新：`screen_cast 客户端(单播/组播) | 教师端 IP | FPS | 丢包% | 延迟 ms | 队列`
- 延迟 = 接收时刻 − 教师端采集时刻；跨机器时钟不同步（差值 > 500ms）显示 `--`
- 队列上限 4 帧，超出丢积压保实时

## 7. 实测数据

### 7.1 端到端（本机 2560x1600）
- 单播全链路：采集→编码→分包→UDP→重组→解码→渲染，12 秒收包 6000+，解码 330+ 帧
- **端到端延迟 16–63ms**（满足 <100ms 目标）
- 差分协同：53 帧采集仅发 9 帧（跳过 44），客户端 9/9 解码

### 7.2 组播 40 客户端压力测试（`stress_test.sh 40 20`）
- **40/40 客户端全部收流**，总收包 272,362，**总丢帧 0**
- 验证组播特性：一份教师端带宽服务所有客户端（客户端数不影响带宽）

### 7.3 FEC 抗丢包（`diag_fec.exe 1 10`）
- 1% 随机丢包：**80% 受损帧被 FEC 救回**（44/55），解码器保持健康
- 0% 丢包基线：解码 301/345（其余为 P 帧不产出的正常现象）

### 7.4 带宽优化
- 差分：静态屏省带宽约 44%
- 清晰度档位：高清 1080p/8Mbps、标清 720p/4Mbps、流畅 480p/2Mbps（推流中可实时切换）

### 7.5 v3.6 稳定性验证（2026-08-12）
- **30 分钟压测**（`teacher_cli --adaptive` 单播 + client_gui）：4 次教师端杀进程重启，60 采样点全部 `responding=True`，内存 109~138MB 无泄漏，**0 崩溃 / 0 失败**
- **组播多客户端**（1 教师端 + 4 console + 1 GUI，12 分钟）：教师端重启后 **5/5 自动重连**，解码成功 8543 帧仅 3 起始失败，FEC 恢复 0 / 丢帧 0
- **自适应码率**：注入 50% 丢包 → 目标码率 **6000 → 1965 kbps** 阶梯下降

## 9. 开发路线回顾

1. **阶段一：单播 1:1**（联调打通全链路）✅
2. **阶段二：GUI + 差分投屏**（教师端界面、预览、清晰度、脏区可视化）✅
3. **阶段三：组播 40 客户端** ✅
   - 客户端加入组播组收流（KEYFRAME 控制仍单播）
   - 教师端关键帧请求限流（防风暴）
   - 教师端周期性自愈关键帧（保证 ≤2s 可入画）
   - 组播地址可配置（多教室并行）
4. **增强：FEC 前向纠错 + 智能关键帧请求** ✅
5. **验证：40 客户端压力测试 + FEC 丢包验证** ✅
6. **v3.6：自适应码率（AIMD）+ 自动重连** ✅
   - 客户端 REPORT 丢包上报 → 教师端 AIMD 调码率 → 编码器重建自动带 IDR
   - 断流 >5s 自动重连（重置预热/序列 + 强制关键帧 + 解码器重同步）
   - 验证：30 分钟压测（4 次教师端重启 0 崩溃 0 卡死）+ 组播 5 客户端并发（5/5 自动重连）

## 10. 已知限制与未来工作

### 已知限制
- **FEC 能力**：K=2 上限（1 片 100% 恢复；同组 2 片 / 3 片以上无法恢复）；3%+ 高丢包下大关键帧难以存活（LAN 场景罕见）
- **跨机器时钟**：延迟统计依赖教师端时间戳，时钟不同步时显示 `--`
- **多网卡**：组播 `INADDR_ANY` 默认接口，多网卡机器需指定网卡
- **单机多客户端**：同机多客户端共享 CPU 解码，测试中 FPS 会下降（真实部署各客户端独立机器）

### 未来工作
- FEC 强度可配置（K 值/按帧类型差异化）
- NACK 选择性重传（组播下按需单播重发）
- 多教室多组地址冲突检测
- 一键启动批处理脚本 / 部署打包
